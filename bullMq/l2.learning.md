## This document contains the details regarding the DLQ(Dead Letter Queue), Job LifeCycle,  Queue Events and FlowProducer.

# Life Cycle of a job.

A job has following stages as it lifecycle. All of the stages are mentioned below.
- waiting -> Job is waiting for a worker.
- active -> Worker is processing the job.
- completed -> Worker successfully finished the job.
- failed -> Processing of job inside the worker is failed.
- delayed -> Job will become eligible later.
-  waiting-children -> Parent job is waiting for its child job(s) to get processed.
- paused -> Job is held because its queue is paused.


# Listning for the events

```
import { QueueEvents } from 'bullmq';
const queueEvents = new QueueEvents('queueName');

queueEvents.on('waiting', ({ jobId }) => {
  console.log(jobId, 'waiting');
});

queueEvents.on('active', ({ jobId }) => {
  console.log(jobId, 'active');
});

queueEvents.on('completed', ({ jobId, returnvalue }) => {
  console.log(jobId, 'completed', returnvalue);
});

queueEvents.on('failed', ({ jobId, failedReason }) => {
  console.log(jobId, 'failed', failedReason);
});

```
In the Queue Events we pass the name of the Queue, for which we want to keep track the lifecycle of its job.

### Ex- Listning the events for the 'EMAIL' Queue.
```
import { QueueEvents } from 'bullmq';
const emailEvents = new QueueEvents('EMAIL')

emailEvents.on('completed', ({ jobId, returnvalue }) => {
  console.log(jobId, 'completed', returnvalue);
});

emailEvents.on('failed', ({ jobId, failedReason }) => {
  console.log(jobId, 'failed', failedReason);
});
```
