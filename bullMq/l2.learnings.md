# Life Cycle of a job.

A job has following stages as it lifecycle. All of the stages are mentioned below.
- waiting -> Job is waiting for a worker.
- active -> Worker is processing the job.
- completed -> Worker successfully finished the job.
- failed -> Processing of job inside the worker is failed.
- delayed -> Job will become eligible later.
-  waiting-children -> Parent job is waiting for its child job(s) to get processed.
- paused -> Job is held because its queue is paused.


# Listning for the events

```
import { QueueEvents } from 'bullmq';
const queueEvents = new QueueEvents('queueName');

queueEvents.on('waiting', ({ jobId }) => {
  console.log(jobId, 'waiting');
});

queueEvents.on('active', ({ jobId }) => {
  console.log(jobId, 'active');
});

queueEvents.on('completed', ({ jobId, returnvalue }) => {
  console.log(jobId, 'completed', returnvalue);
});

queueEvents.on('failed', ({ jobId, failedReason }) => {
  console.log(jobId, 'failed', failedReason);
});

```
In the Queue Events we pass the name of the Queue, for which we want to keep track the lifecycle of its job.

#### Ex- Listning the events for the 'EMAIL' Queue.
```
import { QueueEvents } from 'bullmq';
const emailEvents = new QueueEvents('EMAIL')

emailEvents.on('completed', ({ jobId, returnvalue }) => {
  console.log(jobId, 'completed', returnvalue);
});

emailEvents.on('failed', ({ jobId, failedReason }) => {
  console.log(jobId, 'failed', failedReason);
});
```



# Handling of the failed jobs And DLQ(Dead Letter Queue)

## Configuring the Redis
```
import IORedis from "ioredis";

export const connection = new IORedis({
  host: "127.0.0.1",
  port: 6379,
  maxRetriesPerRequest: null,
});
```
#### maxRetriesPerRequest in ioredis specifies how many times a Redis command can be retried when Redis is unavailable before the command fails with an error.
#### Ex-
```
const connection = new Redis({
  host: '127.0.0.1',
  port: 6379,
  maxRetriesPerRequest: 3
});
```
- 3: A command can be retried up to the configured limit before failing.
- 0: No retries for a failed request.
- null: Commands can wait indefinitely for Redis to become available, subject to other connection and retry settings.

## Setting up the producer
```
import { emailQueue } from "./queues.js";

await emailQueue.add(
  "send-email",
  {
    from: "uttam111@gmail.com",
    to: "uttam123@example.com",
    subject: "This is a test mail",
  },
  {
    attempts: 3,
    backoff: {
      type: "exponential",
      delay: 1000,
    },
  }
);

```

#### attempts: 3. -> This signifies that the job can be processed up to 3 times in total, including the initial attempt. If all three attempts fail, the job enters the failed state.

#### backoff.type: "exponential" -> This signifies that the delay between retries increases exponentially.

#### backoff.delay: 1000 -> This signifies the delay.
#### The delay will get calculated as `delay=initialDelay*[2^(retry-1)]`


## Setting up the consumer and the DLQ
```
import { Worker } from "bullmq";
import { deadLetterQueue } from "../../broker/queues.js";
import connection from '../../config/redis.config.js'

const worker = new Worker(
  "email-queue",
  async (job) => {
    console.log("Processing:", job.name, job.data);

    // Simulate an email service and if fails then throw error
    throw new Error("Email service unavailable");
  },
  { connection }
);

worker.on("failed", async (job, error) => {
  if (!job) return;

  // Wait until all configured attempts are exhausted
  if (job.attemptsMade >= (job.opts.attempts ?? 1)) {
    try {
      await deadLetterQueue.add(
        "failed-email",
        {
          originalJobId: job.id,
          originalJobName: job.name,
          originalData: job.data,
          failedReason: error.message,
          attemptsMade: job.attemptsMade,
          failedAt: new Date().toISOString(),
        },
        {
          jobId: `failed-${job.id}`,
        }
      );

      console.log(`Job ${job.id} moved to DLQ`);
    } catch (dlqError) {
      console.error("Failed to enqueue DLQ job:", dlqError);
    }
  }
});

worker.on("error", (error) => {
  console.error("Worker error:", error);
});
```

#### Worker also accepts the connection object.


## Create a decicated Worker to process the Jobs from a DLQ.
```
import { Worker } from "bullmq";
import { connection } from "./queues.js";

const dlqWorker = new Worker(
  "email-dlq",
  async (job) => {
    console.log("Dead letter job:", job.data);

    // Log the failure, alert an administrator,
    // or save the failure details to a database.
  },
  { connection }
);

dlqWorker.on("completed", (job) => {
  console.log(`DLQ job ${job.id} handled`);
});

dlqWorker.on("failed", (job, error) => {
  console.error("DLQ processing failed:", error.message);
});
```
